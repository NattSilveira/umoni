# Contribuindo com o Umoni

## Commits

Use mensagens curtas, objetivas e no imperativo, seguindo este formato:

`tipo: descrição da alteração`

Tipos recomendados: `feat`, `fix`, `style`, `refactor`, `docs`, `test` e `chore`.

Exemplos:

- `fix: corrige menu mobile no iPhone`
- `feat: adiciona planejamento mensal`
- `style: ajusta identidade visual sazonal`

Cada commit deve representar uma alteração coerente e validada.

## Pull Requests

Pull Requests devem explicar o problema, a solução, os testes realizados e qualquer ponto pendente. Alterações visuais devem ser verificadas em desktop e dispositivos móveis.

Antes de abrir um Pull Request:

1. Verifique o status do Git.
2. Execute os testes ou validações disponíveis.
3. Remova arquivos temporários e dados pessoais.
4. Revise o diff completo.
